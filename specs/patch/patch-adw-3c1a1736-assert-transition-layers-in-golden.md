## Issue Summary

**Original Spec:** `specs/issue-157-adw-3c1a1736-sdlc_planner-transitions-tied-to-phrases.md` (task 14)
**Issue:** The `rethink-work-transitions` fixture is only compared byte for byte with its committed golden. Nothing checks what that golden holds, so a golden regenerated by `scripts/golden.ts` that dropped a layer or a level would still pass both test projects.
**Solution:** Add one shared test helper that reads the transition layers and their level children out of a built page. Then add a test, in both `build.test.ts` and `build.browser.test.ts` (both loop over the same `FIXTURES` list), that builds `rethink-work-transitions` and asserts three things: four `class="clip layer"` elements, kinds `dim`, `numbered`, `numbered`, `panel` (each of the three kinds present), and each layer's `-number`, `-lead` and `-key` texts. The texts are checked against literal values and against the edit's `levels`.

## Files to Modify

Use these files to implement the patch:

- `packages/edit/src/test-support/transition-layers.ts` (new): the HTML reader shared by both test projects.
- `packages/edit/src/build.test.ts`: the Node assertion.
- `packages/edit/src/build.browser.test.ts`: the same assertion on the Chromium build.

## Implementation Steps

IMPORTANT: Execute every step in order, top to bottom.

### Step 1: Add the shared reader `test-support/transition-layers.ts`

- Export `transitionLayers(html: string): { id: string; levels: Record<string, string> }[]`. It has no platform API, so the Node and browser projects can both import it.
- Layers: match every `<div id="([^"]+)" class="clip layer"` in document order (the builder writes `id` first and then `class`, see `build.ts` around line 255).
- Levels: for each layer id, match `<div id="<id>-(number|lead|key)" class="level [^"]*" style="[^"]*">(.*?)</div>` (escape the id for the regex). Map the level name to its inner text with `<br />` replaced by a single space, so `the way<br />we work` reads `the way we work`, which is the edit's `levels.key.text`.
- Add a header comment of one or two lines saying what it reads and why: the goldens are compared byte for byte, so this checks what they hold. No em-dashes.

### Step 2: Assert it in `build.test.ts`

- Add `it("rethink-work-transitions holds one layer per kind with its level texts", ...)`. Take the fixture from `FIXTURES` by name and build it with `goldenOf(fixture, await nodeMeasurer())`. Run `transitionLayers` on both `built.html` and `GOLDENS["rethink-work-transitions"]!.html`, so the committed golden itself is checked too.
- Assert `html.match(/class="clip layer"/g)` has length 4.
- Assert `fixture.edit.tracks.transitions!.map((t) => t.type)` equals `["dim", "numbered", "numbered", "panel"]`. The reader's ids must equal the transitions' ids in order (`transition-1` to `transition-4`), so each kind has exactly one layer element per transition and every kind is present.
- Assert the reader's result `toEqual` this literal list, which pins the golden's content apart from the edit file:
  - `transition-1`: `{ lead: "AI has completely disrupted", key: "the way we work" }`
  - `transition-2`: `{ number: "1", lead: "they want", key: "fair pay" }`
  - `transition-3`: `{ number: "2", lead: "protected", key: "mental health" }`
  - `transition-4`: `{ lead: "work should", key: "fund life not take it over" }`
- Also assert, per transition, that the reader's levels equal the edit's `levels` texts (`Object.fromEntries` of the defined `number`, `lead` and `key` entries mapped to `.text`). For numbered transitions also assert `levels.number.text === String(t.number)`. Then the edit's `levels` and the page cannot disagree.

### Step 3: Assert it in `build.browser.test.ts`

- Add the same test there, building with `goldenOf(fixture, await browserMeasurer())`. Import `transitionLayers` and keep the literal expected list. To avoid duplicating it, export it as `TRANSITION_LEVELS` from `transition-layers.ts` and use it in both files, so knip sees each export used.
